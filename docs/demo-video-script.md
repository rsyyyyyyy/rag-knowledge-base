# NexusMind 文献知识库演示视频脚本

目标时长约 7 分 35 秒，可在 5—8 分钟内调整。整段视频围绕一个任务展开：**研究 Agent 的评估方法，从整理文献，到理解一篇论文，再核对原文并比较两种方案。** 技术原理随操作自然解释，不另设技术总结环节。

“旁白”可直接朗读，“画面操作”供录制时参考。回答内容、页码与引用编号以实际界面为准。

## 一、录制准备

- 使用当前前端开发服务的实际地址。此前演示地址为 http://127.0.0.1:5176/，重新启动后以终端显示为准。
- 确认后端和模型 API 可用，知识库包含已经完成索引的 `AgentAuditor.pdf` 与 `Multi-Agent-as-Judge.pdf`。
- 建议使用 1920×1080 分辨率，确保打开右侧 PDF 后，左侧回答与右侧高亮都清晰可读。
- 新建演示会话，开启“知识库检索”，初始范围选全库。所有主线问题在同一会话中依次发送。
- 上传操作可提前录成短片，展示上传、处理中和可检索状态，再回到已有文献。不要为了录制删除现有论文或重复上传同一文件。
- 问答完成且引用核验结束后再点击编号。可剪去或加速等待时间，画面注明“已加速等待”。
- 这次只修改讲稿，没有重新调用模型。文末保留前次接口验证记录，录制前需在当前版本演练，检查回答及引用定位。

## 二、一个研究任务的完整演示

### 00:00—00:40 带着研究问题进入项目

**画面操作**

打开 NexusMind，切换到知识库管理。画面展示已经收录的 Agent 研究文献。

**旁白**

大家好，我们的项目叫 NexusMind，是一个面向文献阅读与研究的智能知识库。

假设现在我们要了解一个研究问题：怎样评估一个 Agent 的表现？我们已经收集了几篇相关论文，接下来需要弄清每篇论文采用什么方法、结论有什么依据，以及不同方案之间有哪些区别。

今天就围绕这个任务，完整演示一次从管理文献、提出问题，到检查证据和比较方法的阅读过程。

### 00:40—01:20 把研究材料放进知识库

**画面操作**

展示文件夹与文献列表，插入简短上传画面，停留在“可检索”状态。指出两篇示例文献的位置。

**旁白**

首先，把收集的 PDF 上传到知识库，按文件夹整理。这里可以查看文献状态，也可以搜索和编辑书目信息。

文件上传之后，后台会完成正文解析、分块和索引。这个过程中，系统会记录文献、章节、正文片段之间的关系，同时保留片段所在的页码和页面位置，为后面的检索与原文定位做准备。

等状态变成可检索，就可以围绕这些材料提问。接下来，我们使用库里已经处理好的论文继续演示。

### 01:20—02:00 先确认手头有哪些材料

**画面操作**

进入智能问答，输入问题 1。回答完成后，在清单中指出 AgentAuditor 与 Multi-Agent-as-Judge。

**问题 1**

```text
当前知识库有哪些文献？
```

**旁白**

开始阅读之前，我先问：当前知识库有哪些文献？

这个问题查询的是整个库的目录。系统会理解问题类型，读取实际文献记录，返回当前范围内的清单。

这里使用了分层处理：查目录时访问书目数据，了解整篇论文时走文献阅读流程，询问方法细节时再检索具体段落。让不同问题找到对应的数据层，是准确回答的第一步。

有了清单，我们先了解这些文献各自在研究什么，再决定从哪一篇开始细读。

### 02:00—02:45 总结全库文献，建立整体认识

**画面操作**

保持全库范围，输入问题 2。回答完成后，滚动展示逐篇概述和最后的综合归纳，对照上一轮清单检查是否覆盖全部文献。较长等待剪辑或加速，并标注“已加速等待”。

**问题 2**

```text
请总结当前知识库中的所有文献：逐篇列出文献名称，用两到三句话概括各自的研究问题和核心方法，最后归纳它们的共同主题与主要区别。请依据文献内容并附原文引用；未能读取或证据不足的文献请单独说明，不要遗漏或猜测。
```

**旁白**

接下来，请助手总结知识库中的所有文献，逐篇介绍研究问题和核心方法，再归纳共同主题与区别。

这次要回答的是内容层面的全库概览，需要先确定有哪些文献，再结合各篇正文组织总结。对于长文，系统采用分批阅读和带来源的汇总，将概览与支撑它的原文关联起来。

这样的概览帮助我们建立整体认识，选择下一步重点阅读的材料。这里我们继续打开 AgentAuditor，具体看看它的方法流程。

### 02:45—03:10 选定一篇论文开始阅读

**画面操作**

输入问题 3，展示助手确认文献并提供阅读选项。

**问题 3**

```text
AgentAuditor.pdf
```

**旁白**

我输入文件名，助手会确认这篇文献是否可检索，并提示可以概览内容、讲解方法与实验，或者与其他论文比较。

我们的研究任务是比较评估方法，所以先从这篇论文的方法流程入手。

### 03:10—04:20 弄清方法流程，解释怎样找准证据

**画面操作**

输入问题 4。回答完成后，让观众看清三个阶段及其引用。此处先停留在回答区，下一段再点击引用。

**问题 4**

```text
这篇论文的方法分为哪三个阶段？请引用原文。
```

**旁白**

这里问：这篇论文的方法分为哪三个阶段？请引用原文。

回答列出了特征记忆构建、推理记忆构建和记忆增强推理。这些是 AgentAuditor 论文提出的方法，我们通过它来展示系统如何查阅文献。

对于这种具体问题，系统会把提问转成检索线索。比如中文问题涉及英文论文时，可以使用对应的英文术语找证据。

检索同时利用语义向量和全文匹配：前者寻找意思相近的段落，后者保留方法名、缩写等精确线索，再融合两路排名。模型还可以调用章节和片段读取工具，查看候选段落的上下文。

找到候选内容后，系统会检查证据是否回答了用户要求的要点，必要时在预算内补查。所以，搜索命中只是开始，还需要判断原文是否足以支撑这次回答。

### 04:20—05:40 点开结论，核对原文和高亮位置

**画面操作**

点击“三个阶段”结论旁的引用编号，右侧打开 PDF，展示页码和黄色高亮。再点击另一处引用，让观众看到高亮切换。

保持右侧打开，在左侧输入问题 5。回答完成后点击新引用，展示进一步解释来自另一处原文。

**问题 5**

```text
第二个阶段具体做什么？请引用原文。
```

**旁白**

现在点击引用，右侧会打开对应的 PDF，并用黄色高亮标出证据。左边是系统的解释，右边是论文原文，我们可以直接检查“三个阶段”这个结论有没有依据。

这个位置是怎样找到的？解析 PDF 时，系统保存了文字与页面坐标之间的映射。回答中的引用还会回到原文校验：检查引用文字是否确实存在、来源是否对应，并核对它能否支持相应表述。

确认引用后，再把原文位置映射到页面上的矩形区域，交给前端绘制高亮。因此，解释、证据和页面位置能够关联起来。具体定位精度仍取决于 PDF 的解析结果。

接着我问：第二个阶段具体做什么？助手会继续查阅推理记忆构建的内容，并给出对应依据。我们可以保持原文预览打开，在左侧继续问、在右侧继续核对，整个阅读过程都在同一个工作区里完成。

### 05:40—07:05 把两种评估方法放在一起比较

**画面操作**

输入问题 6，展示分别列出两篇论文方法的回答。先点击 AgentAuditor 的引用，再点击 Multi-Agent-as-Judge 的引用，右侧切换源文件。

**问题 6**

```text
对比 AgentAuditor.pdf 和 Multi-Agent-as-Judge.pdf 的核心研究方法，请分别给出原文依据。
```

**旁白**

了解第一篇论文之后，我们把它和 Multi-Agent-as-Judge 放在一起比较，看看两种方案怎样完成评估。

这次问题里有两篇论文和一个明确维度：核心研究方法。系统会围绕同一个维度分别为两篇论文取证，检查双方的材料是否充分。某一边证据缺失时，可以定向补查，并对仍然无法确认的部分保留边界。

从本次回答可以看到，AgentAuditor 强调记忆增强的评估推理；Multi-Agent-as-Judge 则通过人格构建、组内辩论和聚合评分组织多智能体评估。

我们可以依次点击两边的引用，核对这些描述分别来自哪篇论文、哪一处原文。同一个文件的多个证据也会归到一个文件入口，便于集中查看。

这样，一次比较就同时给出了方法信息和查证路径。研究者可以据此继续阅读实验设计、适用条件和局限，再判断哪一种思路适合自己的任务。

### 07:05—07:35 回到研究任务，结束展示

**画面操作**

停留在左侧比较结果、右侧原文高亮的分栏界面，最后切回文献列表。

**旁白**

到这里，我们已经完成了一次文献阅读任务：确认并概览手头的材料，理解一篇论文的方法，检查结论的原文依据，再比较两种研究方案。

NexusMind 把这些操作连接起来，让用户能够带着问题阅读，也能够沿着证据检查回答。后续我们会继续完善复杂文献解析和问答质量评测。以上就是我们的项目展示，谢谢大家。

3. `AgentAuditor.pdf`
4. `这篇论文的方法分为哪三个阶段？请引用原文。`
5. `第二个阶段具体做什么？请引用原文。`

## 四、时长与录制取舍

- 时间标记是剪辑目标，包含朗读、输入、回答停留、点击与适量等待，不是接口响应承诺。
- 按正常语速试读一次，再分配操作时间。等待较长时可加速，不要为了卡时长快速略过原文高亮。
- 压缩至 5 分钟时，将开场与入库合计缩至 50 秒，文件名选择缩至 10 秒；保留目录与正文的分层说明、引用校验、坐标定位及跨论文比较。
- 接近 8 分钟时，可在第四个问题后多停留几秒阅读证据，或增加一次引用切换；无需补上单独的技术亮点总结。
- 通用聊天、联网找论文和单篇长文的完整细读不放进本次主线，避免打断研究任务。需要补充功能画面时，可另录为片尾素材。

## 五、前次验证记录与技术表述依据

以下是此前在运行中后端的接口验证结果，这次改稿未重新验证；接口结果不等同于浏览器点击验收。新增的全库总结问题尚未实测，录制前需检查逐篇覆盖、引用和总耗时。全库阅读可能明显长于单篇问答，45 秒是成片展示预算，等待过程需另行剪辑。

- 文献清单：返回 9 篇真实记录，约 0.7 秒。录制当天以实际数量为准。
- 输入 AgentAuditor 文件名：返回记录、可检索状态及阅读建议，约 1 秒。
- 紧接文件名问三个阶段：约 7.8 秒，返回 3 处原文引用，均带页面坐标，前次落在 PDF 第 4 页。
- 继续问第二阶段：约 12.3 秒，返回推理记忆构建的说明，附第 5 页原文及坐标。回答较简短，适合展示进一步查证，不宜预设一定会输出长篇细节。
- 两篇论文的方法对比：约 9.3 秒，返回两篇论文共 6 处引用；工具轨迹包含卡片、章节列表、片段和章节读取，两篇论文的方法要点覆盖检查均为 full。这仅代表当次问题维度的核验结果。
- 此前全文概览约需 86.7 秒，另一次宽泛追问出现过 HTTP 502，因此不安排为主片必须完成的步骤。正式录制前仍需演练当前版本。

脚本中的技术说明对应以下代码，供准备时查阅，不需要在视频中展示代码：

- `backend/question_router.py`：问题类型、阅读模式、检索线索和比较维度。
- `backend/knowledge_search.py`：分层读取、向量与 FTS5 检索、RRF 排名融合。
- `backend/literature_tools.py`：章节和原文工具调用及预算限制。
- `backend/evidence_coverage.py`：按问题维度检查证据、定向补查。
- `backend/evidence_grounding.py`：引用文字匹配、来源检查与原文位置映射。语义支持包含模型判断，不能描述为绝对正确的证明。
- `backend/pdf_evidence.py`：解析 PDF 并保存文字、页面与坐标映射。
- `frontend/src/components/ReferenceSources.tsx`、`PdfReferencePreview.tsx`：来源组织、右侧预览与高亮绘制。

录制时注意区分：AgentAuditor 的记忆增强评估方法属于论文内容；本项目展示的是围绕这篇论文进行检索、理解和证据核验的能力。
